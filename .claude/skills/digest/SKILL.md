# Digest

記事や登壇資料のURLを受け取り、その資料を主題とするページを1件、対話なしで書き切る。

[ingest](.claude/skills/ingest/SKILL.md) との違いは主題の置き方にある。ingest は用語や道具を主題に置き、情報源はその材料として使う。digest は資料そのものを主題に置き、誰がどこで何を言ったかを記録する。そのため ingest の境界にある「情報源の要約を作らない」は digest では成り立たず、要旨は資料の要約になる。膨らませない理由のほうは同じで、既存ページとの接続を持たない説明は、資料に書いてあっても書かない。

途中で問いを立てない。判断が分かれる点はこの文書の規則で決め、決めたことを報告に残す。規則で決められないならその部分を書かずに報告する。ユーザーは差分を読んで直せるが、黙って足された理解は気づかれない。

## 適用範囲

扱うのは、ページの主題が資料そのものになるURL。技術ブログ、ニュース記事、登壇資料、リリースノート、公式ドキュメントの解説ページが該当する。

URLの指す先がツールや製品の公式サイトで、主題が資料ではなくその対象になるなら ingest へ回す（Scalafix の公式サイトは Scalafix というページになる）。判断が付かないURLも ingest へ回す。

## 境界

- 既存ページを一切変更しない。新しいページからのリンクだけで接続し、被リンクは自動計算に任せる。既存ページ側のリンク化は日本語の語境界による文脈判定が要るため、ingest の第4節でユーザーと行う。
- 作るページは資料1件につき1ページ。複数のURLを渡されたら順に1件ずつ作り、1ページへ束ねない。
- 資料が言及する概念のページを併せて作らない。
- 人物・組織・媒体のページを新規に作らない。既存ページが無ければ素のテキストで書く。
- 新しいタグを作らない。既存タグに合うものが無ければタグ行を短くする。
- ウィキ全体の整理や検査へ作業を広げない。

## 1. 資料と土台を読む

1. 資料を取得する。`.github/rss-to-scrap/feeds.yml` に載っている feed の記事なら `mise run fetch-article-body -- --url "<URL>"` で全文が取れる。何も出なければ WebFetch を使う。
2. 取得できた範囲を確かめる。Speaker Deck のようにスライド本文が取れず、題名と概要しか読めないことがある。取れた範囲だけで書き、取れなかったことを報告に残す。憶測で補完しない。
3. 中心となる用語と主張を特定する。
4. 語を変えながら `mise exec -- scraps search "<query>" --json` で関連ページを探す。
5. `mise exec -- scraps tag list --json` で既存タグを確認する。
6. 関連上位3–8件を `mise exec -- scraps get "<title>" [--ctx "<ctx>"] --json` で読む。
7. 中心の用語を、既存ページがある語と無い語に分ける。前者はリンクで済ませ、後者は今回書かない。
8. 資料の題名で `mise exec -- scraps get "<題名>" --json` を引き、同名ページの有無を確かめる。

## 2. ページを書く

本文の執筆規律は [ingest](.claude/skills/ingest/SKILL.md) の「3. ページを書く」に従う。digest では次のように読み替える。

- 「対話で確立した内容だけを書く」は、資料から確認できた内容だけを書く、と読む。
- 略語の第2階層見出しは使わない。タイトルは資料の題名をそのまま使い、訳したり縮めたりしない。
- 「仕様詳細、手順、網羅的な利用例を転記しない」はそのまま効く。理由は要約になるからではなく、接続を持たない説明だから。

形は次のとおり。

```
#[[タグ]] #[[タグ]]

<要旨。誰が・どこで・何を言っているか。1–2文>

- <既存ページとの接続を担う箇条書き。0–3件>

<URL>

[[Blog|ブログ]]
```

- 要旨には著者と発表の場を入れる。既存ページのある人物・組織はリンクし、無ければ素のテキストにする。日付や所属は資料から確認できたものだけ書く。
- 箇条書きは接続を担うものだけ。資料の目次や章立てをそのまま並べない。0件で構わない。
- URLは `<...>` で囲んで置く。スライドの埋め込み（iframe）は使わない。
- `[[Blog|ブログ]]` は最終行に置く。技術ブログとニュース記事が対象で、登壇資料と公式ドキュメントには付けない。

配置は既定で ctx なし（`scraps/<題名>.md`）。第1節8で同名ページが見つかったときだけ ctx を付け、記事は `scraps/Blog/<題名>.md`、登壇資料は `scraps/Slide/<題名>.md` に置く。

## 3. 検証して報告する

1. 書いた本文を読み返し、リンクを持たない説明が残っていないか確かめる。
2. 使用したタグが既存タグであることを確認する。
3. `mise exec -- scraps lint --rule broken-link` を実行する。
4. 差分を読み、作成した1ファイル以外を変更していないことを確認する。
5. 作成したページとそのタグ・リンク、資料から取得できなかった部分、ctx を付けたならその理由、今回の変更と無関係な警告を分けて報告する。
